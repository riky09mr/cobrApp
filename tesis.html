Antecedentes Las empresas que otorgan créditos o venden a plazos dependen de la recuperación oportuna de sus carteras para mantener su flujo de caja y su capacidad de otorgar nuevos financiamientos. Tradicionalmente, la gestión de cobranzas se ha realizado mediante planillas electrónicas, cuadernos de registro y llamadas telefónicas, métodos que resultan insuficientes cuando la cartera de clientes crece y los cobradores operan en campo. En los últimos años, diferentes estudios y desarrollos tecnológicos han evidenciado la importancia de automatizar los procesos de cobranza. Plataformas web y aplicaciones móviles especializadas han permitido reducir los niveles de morosidad, optimizar los recursos humanos y mejorar la eficiencia operativa de las organizaciones. Sin embargo, la mayoría de las soluciones disponibles en el mercado son costosas, están orientadas a grandes empresas o no se adaptan a las particularidades del contexto local, como la necesidad de operar con múltiples empresas desde una única plataforma o el trabajo de cobradores en zonas con conectividad intermitente. ## 1.2. Descripción de la Problemática Actualmente, muchas empresas que otorgan créditos o venden a plazos enfrentan dificultades para gestionar sus cobranzas de forma organizada. El uso de métodos manuales, planillas o sistemas poco integrados genera retrasos, errores en los registros y problemas para supervisar las gestiones de cobranza en tiempo real. Entre los problemas más comunes se encuentran: - **Falta de visibilidad en tiempo real** sobre el estado de las cobranzas y de las gestiones realizadas por cada cobrador. - **Duplicación de tareas y cobranzas en vano** por la falta de una asignación clara de clientes y zonas. - **Imposibilidad de supervisar el trabajo del cobrador en campo**, incluyendo su ubicación geográfica y los resultados de sus visitas. - **Pérdida de datos y errores** derivados del registro manual de pagos y gestiones. - **Demoras en la toma de decisiones** por la ausencia de reportes actualizados y confiables. - **Falta de control sobre la caja diaria**, los comprobantes emitidos y los medios de pago utilizados. - **Falta de una herramienta para supervisar el desempeño de los cobradores** y de comunicación directa entre supervisores y personal de campo. ## 1.3. Solución Propuesta El presente proyecto propone el desarrollo de un sistema automatizado de cobranzas multiempresa que permita centralizar y agilizar todas las gestiones relacionadas, mejorando la organización y el seguimiento de los cobradores en campo. La herramienta contará con una plataforma web administrativa y una aplicación móvil para cobradores, facilitando la asignación de tareas, el registro de cobranzas y la comunicación entre supervisores y cobradores de forma rápida y eficiente. Además, el sistema permitirá implementar notificaciones, reportes de gestión, alertas por cobranzas vencidas y módulos de geolocalización para organizar las zonas de cobertura, optimizando los recursos humanos y garantizando un control más riguroso de las operaciones. La utilización de esta solución tecnológica no solo reducirá la carga administrativa y los errores por registros manuales o duplicados, sino que también mejorará significativamente la transparencia y el control sobre las gestiones realizadas. Esto se traducirá en una mayor recuperación de deudas, una mejor toma de decisiones y una experiencia de trabajo más organizada para el personal operativo y administrativo. ## 1.4. Sistemas de Información Un sistema de información (SI) es un conjunto de componentes interrelacionados que recolectan, procesan, almacenan y distribuyen información para apoyar la toma de decisiones, la coordinación y el control en una organización (Laudon & Laudon, 2020). Todo sistema de información está compuesto por cinco elementos fundamentales (Kendall & Kendall, 2019): 1. **Hardware:** equipos físicos como servidores, dispositivos móviles y estaciones de trabajo. 2. **Software:** programas y aplicaciones que procesan los datos. 3. **Datos:** hechos en bruto que son procesados para generar información útil. 4. **Procedimientos:** reglas y políticas que definen cómo opera el sistema. 5. **Personas:** usuarios finales, administradores y personal de soporte. En cobrApp, el registro de cobros y la gestión de visitas constituyen un Sistema de Procesamiento de Transacciones (TPS); el panel de control y los reportes de cobranzas conforman un Sistema de Información Gerencial (MIS); y los análisis de morosidad y desempeño de cobradores funcionan como un Sistema de Soporte a Decisiones (DSS). ### 2.2. Gestión de Cobranzas La gestión de cobranzas comprende el conjunto de procesos, estrategias y herramientas orientadas a recuperar los créditos otorgados por una organización dentro de los plazos establecidos. Su objetivo principal es minimizar la morosidad y las pérdidas por incobrabilidad, manteniendo una relación comercial saludable con el cliente (Sagner, 2011). Los indicadores clave de la gestión de cobranzas incluyen: el índice de morosidad, el monto recuperado por período, el número de gestiones realizadas, el promedio de cobro por cobrador y la antigüedad de la cartera. Estos indicadores, calculados automáticamente por cobrApp, permiten a los supervisores identificar riesgos tempranos y tomar acciones correctivas. ### 2.3. Arquitectura de Software La arquitectura de software define la estructura de los componentes de un sistema, sus relaciones y los principios que guían su diseño y evolución (Bass, Clements & Kazman, 2012). Para el desarrollo de cobrApp se adoptó una **arquitectura cliente-servidor en tres capas** (presentación, lógica de negocio y datos) materializada como una API REST por capas simplificada, en la que: - El **patrón Transaction Script** organiza la lógica de negocio en procedimientos que procesan una transacción a la vez, con acceso directo a la base de datos desde los controladores (Fowler, 2003). Es el patrón dominante en el backend de cobrApp: cada módulo expone controladores que reciben la petición, ejecutan consultas parametrizadas y devuelven la respuesta. - El **patrón Service Layer** define una capa de servicios que encapsula la lógica de negocio y coordina las operaciones de varios controladores (Fowler, 2003). En cobrApp se aplica de forma parcial en el módulo de cobranzas (versión V12), donde los servicios de caja, recibos, numeradores, intereses y feriados (Computus) centralizan reglas de negocio complejas. Esta combinación responde a la complejidad creciente del dominio: Transaction Script ofrece simplicidad y velocidad de desarrollo para operaciones CRUD, mientras que Service Layer aporta consistencia y reutilización en los flujos críticos de cobranza y facturación. ### 2.4. Arquitectura Multiempresa (Multi-Tenant) La arquitectura multiempresa (multi-tenant) permite que una única instancia de software atienda a múltiples organizaciones (inquilinos) compartiendo la misma infraestructura, con aislamiento lógico de los datos de cada una (Chong, Carraro & Wolter, 2006). Existen tres estrategias principales: - **Base de datos por inquilino:** mayor aislamiento, mayor costo. - **Esquema por inquilino:** aislamiento medio. - **Fila compartida:** una sola base de datos y un solo esquema, donde cada tabla incluye una columna de identificación del inquilino. cobrApp adopta la estrategia de **fila compartida**: todas las tablas del sistema incorporan la columna `empresa_id`, y cada consulta filtra los registros por la empresa del usuario autenticado. Esta decisión reduce los costos de infraestructura y simplifica la administración, a la vez que garantiza el aislamiento lógico de los datos mediante control de acceso a nivel de aplicación y de base de datos. ### 2.5. Tecnologías de Desarrollo Web **Node.js** es un entorno de ejecución de JavaScript del lado del servidor, basado en el motor V8 de Chrome, que permite construir aplicaciones escalables y de alta concurrencia mediante un modelo de E/S asíncrono y orientado a eventos (Cantelon et al., 2014). **Express** es el framework web más utilizado sobre Node.js; proporciona un conjunto mínimo de utilidades para enrutamiento, middlewares e integración con motores de plantillas. **React** es una biblioteca de JavaScript para construir interfaces de usuario mediante componentes reutilizables y un modelo de actualización eficiente basado en un DOM virtual (Eisenberg & Zetlen, 2019). **Next.js** es un framework de React que añade renderizado del lado del servidor, generación estática, enrutamiento basado en archivos y optimizaciones de rendimiento, lo que lo hace idóneo para el panel web administrativo de cobrApp. ### 2.6. Desarrollo de Aplicaciones Móviles El desarrollo de aplicaciones móviles puede ser nativo, híbrido o multiplataforma. **React Native** es un framework multiplataforma que permite crear aplicaciones móviles para Android e iOS utilizando JavaScript y React, compilando a componentes nativos reales (Eisenberg, 2020). **Expo** es una plataforma y conjunto de herramientas que simplifica el desarrollo con React Native, ofreciendo acceso a servicios como notificaciones push, cámara, geolocalización y almacenamiento seguro. En cobrApp, la aplicación móvil del cobrador se desarrolló con React Native (Expo), aprovechando: la cámara para las evidencias fotográficas de cada gestión, el GPS para registrar la ubicación del cobro, el almacenamiento local para operar con conectividad intermitente y las notificaciones push para alertas de vencimientos y mensajes del supervisor. ### 2.7. Bases de Datos Relacionales Las bases de datos relacionales organizan la información en tablas relacionadas entre sí mediante claves primarias y foráneas, garantizando la integridad referencial y el soporte de transacciones ACID (Date, 2004). **MySQL** es un sistema gestor de bases de datos relacional de código abierto, ampliamente utilizado por su rendimiento, confiabilidad y facilidad de administración. En cobrApp, la base de datos MySQL 8 almacena las entidades del dominio: `empresas`, `usuarios`, `clientes`, `creditos`, `cuotas`, `zonas`, `asignaciones`, `visitas_cobro`, `arqueos_caja`, `movimientos_caja`, `mensajes`, `facturas`, entre otras. El acceso a los datos se realiza mediante un pool de conexiones MySQL2 y **consultas parametrizadas**, que previenen la inyección SQL. ### 2.8. APIs REST Una API REST (Representational State Transfer) es un estilo arquitectónico para el diseño de servicios web que utiliza los métodos HTTP (GET, POST, PUT, PATCH, DELETE) para operar sobre recursos identificados por URLs (Fielding, 2000). Sus principios incluyen: arquitectura cliente-servidor, ausencia de estado, caché, interfaz uniforme y sistema en capas. La API de cobrApp expone recursos como `/api/usuarios`, `/api/clientes`, `/api/creditos`, `/api/asignaciones`, `/api/cobros`, `/api/caja`, `/api/mensajes` y `/api/facturas`. Cada respuesta se estructura en JSON, y la autenticación se realiza mediante tokens JWT incluidos en el encabezado `Authorization`. ### 2.9. Seguridad Informática La seguridad informática protege la confidencialidad, integridad y disponibilidad de la información. En las aplicaciones web, las amenazas más comunes incluyen la inyección SQL, el cross-site scripting (XSS), la falsificación de solicitudes entre sitios (CSRF) y el acceso no autorizado. cobrApp implementa las siguientes medidas de seguridad: - **Autenticación con JWT (JSON Web Token):** tokens firmados que expiran tras un período configurable, verificados por el middleware `authenticateToken`. - **Hash de contraseñas con bcrypt** (10 rondas), incluyendo contraseñas temporales y cambio obligatorio en el primer acceso (`debe_cambiar_password`). - **Consultas parametrizadas** con MySQL2 para prevenir la inyección SQL. - **Control de acceso basado en roles** (RBAC) con permisos granulares por rol y por empresa. - **Aislamiento multiempresa** mediante el filtrado obligatorio por `empresa_id` en cada consulta. ### 2.10. Geolocalización y Mapas La geolocalización permite determinar la posición geográfica de un dispositivo mediante el GPS, redes Wi-Fi o torres de telefonía móvil. En el ámbito de las cobranzas, la geolocalización posibilita: - Conocer la ubicación en tiempo real del cobrador en campo. - Registrar las coordenadas de cada gestión de cobro, verificando que el cobrador visitó efectivamente la dirección del cliente. - Organizar las zonas de cobertura y optimizar los recorridos. En cobrApp, cada `visita_cobro` registra latitud y longitud, y las zonas geográficas permiten agrupar clientes por área de responsabilidad de cada cobrador. ### 2.11. Control de Acceso Basado en Roles (RBAC) El control de acceso basado en roles (RBAC) asigna permisos a los usuarios según el rol que desempeñan en la organización (Sandhu et al., 1996). Los roles definidos en cobrApp son: | Rol | Descripción | |---|---| | **ADMIN** | Administra todo el sistema: usuarios, empresas, clientes, créditos y reportes. Puede ver y administrar todas las empresas. | | **SUPERVISOR** | Supervisa a los cobradores de su empresa: asigna cobranzas, visualiza gestiones y desempeño del equipo. Solo accede a los datos de su empresa. | | **COBRADOR** | Opera desde la aplicación móvil en campo: visualiza sus asignaciones, registra gestiones, cobros y observaciones. Solo ve sus propias asignaciones. | Los permisos se aplican mediante middlewares como `soloGestor` y `soloCobrador`, y se refuerzan a nivel de consulta para garantizar el aislamiento por empresa. ### 2.12. Notificaciones y Comunicación Las notificaciones push permiten enviar mensajes a los dispositivos móviles de forma proactiva, aun cuando la aplicación no esté en primer plano. En cobrApp, las notificaciones se utilizan para: - Alertar al cobrador sobre cuotas vencidas o próximas a vencer. - Notificar nuevas asignaciones de cartera. - Avisar la llegada de mensajes internos del supervisor. Además, el sistema incorpora un módulo de **mensajería interna** entre supervisores y cobradores, con soporte de imágenes adjuntas, que sustituye a las comunicaciones informales (WhatsApp, llamadas) en los procesos de coordinación de cobranzas. ### 2.13. Optimización de Rutas y Problema del Viajante (TSP) El Problema del Viajante (TSP, por sus siglas en inglés) consiste en encontrar la ruta más corta que visite un conjunto de puntos y regrese al origen. Su resolución óptima es computacionalmente compleja (NP-difícil), por lo que en la práctica se utilizan heurísticas como el vecino más cercano o los algoritmos genéticos (Applegate et al., 2006). En el contexto de cobrApp, la optimización de rutas permite ordenar las visitas diarias de cada cobrador según la ubicación geográfica de los clientes, reduciendo los tiempos de traslado y los costos operativos. Esta funcionalidad constituye una línea de mejora prevista sobre la base de las zonas geográficas ya implementadas. ## Unidad II: Antecedentes — Estado del Arte ### 2.14. Antecedentes Internacionales En el ámbito internacional, existen numerosos sistemas de gestión de cobranzas y cartera, tanto comerciales como académicos. Plataformas como *DebtBook*, *Collect!* o *CrediFlow* ofrecen funcionalidades de automatización de cobros, scoring de clientes e integración con pasarelas de pago; sin embargo, su costo de licenciamiento y su orientación a grandes volúmenes limitan su adopción por parte de las PyMEs. Estudios académicos han demostrado que la digitalización de las cobranzas reduce la morosidad entre un 15 % y un 30 % en empresas de microfinanzas, al mejorar la trazabilidad de las gestiones y la disciplina de pago de los clientes. ### 2.15. Antecedentes Nacionales En Paraguay, la gestión de cobranzas en cooperativas, financieras y casas comerciales se apoya tradicionalmente en sistemas contables genéricos y en el trabajo de campo de los cobradores. Si bien existen iniciativas de digitalización impulsadas por el BNF, la SET (facturación electrónica) y el sector cooperativo, la oferta de soluciones locales de bajo costo, multiempresa y con aplicación móvil para cobradores sigue siendo limitada. cobrApp se posiciona en este nicho, ofreciendo una solución integral adaptada al contexto local, con facturación conforme a la normativa paraguaya (timbrados, establecimientos y puntos de expedición) y soporte de comunicación en español y guaraní. ## Unidad III: Marco Referencial ### 2.16. Definición de Términos Básicos - **Cobranza:** proceso de recuperación de los créditos otorgados por una empresa. - **Morosidad:** condición de las cuotas o créditos cuyo vencimiento no fue satisfecho. - **Cartera:** conjunto de créditos y clientes asignados a una empresa o a un cobrador. - **Asignación:** relación entre un cobrador y un conjunto de cuotas o clientes que debe gestionar. - **Gestión (visita):** acción de cobro o seguimiento realizada por el cobrador con un cliente, registrada con fecha, hora, resultado, evidencia fotográfica y geolocalización. - **Arqueo de caja:** procedimiento de verificación del efectivo y medios de pago recaudados en un período. - **Timbrado:** autorización fiscal otorgada por la SET para la emisión de comprobantes. - **Multiempresa (multi-tenant):** capacidad de un sistema de atender a varias organizaciones con aislamiento lógico de datos. - **JWT:** estándar abierto para transmitir información autenticada entre partes mediante tokens firmados. - **RBAC:** modelo de control de acceso que asigna permisos según el rol del usuario. --- # Capítulo III: Marco Metodológico ## 3.1. Enfoque de Investigación El presente trabajo de investigación adopta un **enfoque mixto**, combinando elementos cuantitativos y cualitativos que se complementan para abordar la complejidad del problema de investigación (Hernández, Fernández & Baptista, 2018). ### 3.1.1. Componente Cuantitativo El componente cuantitativo se manifiesta en la recolección y análisis de datos numéricos relacionados con: - **Indicadores de gestión de cobranzas:** montos recuperados, tasas de morosidad, promedios de cobro por cobrador, cantidad de gestiones realizadas en un período determinado. - **Métricas de rendimiento del sistema:** tiempos de respuesta de la API, consumo de recursos del servidor, cantidad de transacciones procesadas concurrentemente. - **Encuestas estructuradas:** aplicación de cuestionarios a usuarios del sistema para medir niveles de satisfacción, usabilidad y percepción de utilidad mediante escalas Likert. El uso de métodos cuantitativos permite establecer relaciones causa-efecto entre las variables del estudio y generalizar los hallazgos a contextos similares (Creswell & Creswell, 2018). ### 3.1.2. Componente Cualitativo El componente cualitativo se enfoca en la comprensión profunda de los procesos y experiencias de los actores involucrados en la gestión de cobranzas: - **Entrevistas semiestructuradas:** realizadas a administradores de empresas de cobranzas, supervisores y cobradores para comprender sus flujos de trabajo, necesidades no cubiertas y expectativas respecto al sistema. - **Observación directa:** registro de las prácticas actuales de gestión de cobranzas en empresas del sector, identificando puntos de dolor y oportunidades de mejora. - **Análisis documental:** revisión de registros, planillas y reportes existentes en las empresas para comprender el estado actual de sus procesos. La combinación de ambos enfoques responde al principio de **triangulación metodológica**, que permite contrastar y validar los hallazgos desde múltiples perspectivas, aumentando la validez y confiabilidad de los resultados (Denzin, 2017). ## 3.2. Tipo de Investigación ### 3.2.1. Investigación Aplicada Esta investigación se clasifica como **investigación aplicada**, también llamada tecnológica o práctica, ya que tiene como objetivo la solución de un problema concreto del mundo real: la ineficiencia en la gestión de cobranzas debido a la falta de herramientas digitales integradas y multiempresa (Lozada, 2014). En este caso, el producto es cobrApp: un sistema de gestión de cobranzas multiempresa. ### 3.2.2. Investigación Descriptiva Se emplea la **investigación descriptiva** para caracterizar el estado actual de la gestión de cobranzas en las empresas objeto de estudio. Según Hernández, Fernández y Baptista (2018), los estudios descriptivos buscan especificar propiedades, características y rasgos importantes de cualquier fenómeno que se analice. En este contexto, permite describir los procesos manuales o semiautomatizados que utilizan actualmente las empresas de cobranzas en Paraguay. ### 3.2.3. Investigación Correlacional Se utiliza la **investigación correlacional** para analizar la relación entre variables como el uso del sistema y la reducción de la morosidad, o la frecuencia de gestiones registradas y el monto recuperado por cobrador. Si bien no se pretende establecer causalidad estricta, los resultados orientan la toma de decisiones. ### 3.2.4. Investigación Documental y de Campo La investigación es **documental** porque se apoya en el análisis de fuentes bibliográficas, normativas y documentos técnicos; y es **de campo** porque los datos primarios se recolectan directamente de la realidad de las empresas, mediante encuestas, entrevistas y observación. ## 3.3. Diseño de la Investigación El estudio adopta un **diseño no experimental, transaccional (transversal)**, ya que no se manipulan deliberadamente las variables y los datos se recolectan en un momento único del tiempo. Este diseño resulta adecuado para describir el estado de situación de las empresas, evaluar el sistema desarrollado y medir la satisfacción de los usuarios sin alterar su entorno natural (Hernández, Fernández & Baptista, 2018). ## 3.4. Investigación-Acción La construcción del sistema se enmarcó en la **investigación-acción**, un enfoque que combina la generación de conocimiento con la acción transformadora sobre la realidad estudiada (Lewin, 1946). El proceso se desarrolló en ciclos iterativos de **Planificar → Actuar → Observar → Reflexionar**: 1. **Planificar:** identificación de los requisitos funcionales a partir de las necesidades relevadas en las empresas. 2. **Actuar:** implementación de los módulos del sistema correspondientes al ciclo. 3. **Observar:** evaluación del funcionamiento del sistema mediante pruebas funcionales y retroalimentación de los usuarios. 4. **Reflexionar:** análisis de los resultados y ajuste de los requisitos para el siguiente ciclo. Esta dinámica permitió que el sistema evolucionara de forma incremental, incorporando las correcciones detectadas en cada iteración. ## 3.5. Metodología de Desarrollo de Software: Scrum El desarrollo del sistema se gestionó con **Scrum**, un marco de trabajo ágil que organiza el trabajo en iteraciones de duración fija llamadas **sprints** (Schwaber & Sutherland, 2020). Los elementos principales fueron: - **Roles:** Product Owner (representa las necesidades de las empresas), Scrum Master (facilita el proceso) y equipo de desarrollo. - **Artefactos:** Product Backlog (lista priorizada de requisitos), Sprint Backlog (tareas comprometidas para el sprint) e Incremento (funcionalidad terminada al final de cada sprint). - **Ceremonias:** Sprint Planning, Daily Scrum, Sprint Review y Sprint Retrospective. Cada sprint entregó un incremento funcional del sistema, comenzando por la administración de usuarios, siguiendo con clientes y créditos, zonas, asignaciones, cobranzas móviles, caja diaria, mensajería, facturación y reportes. Conclusiones 1. **Sobre el problema investigado:** se confirmó que las empresas que otorgan créditos en Paraguay enfrentan deficiencias significativas en la gestión de sus cobranzas, derivadas del uso de métodos manuales y herramientas poco integradas, lo que genera errores, duplicación de gestiones y falta de supervisión del trabajo en campo. 2. **Sobre el objetivo general:** se desarrolló e implementó cobrApp, un sistema de gestión de cobranzas multiempresa con aplicación web y móvil, que permite administrar múltiples empresas, usuarios, clientes, créditos, asignaciones, cobranzas en campo, caja diaria, mensajería interna, facturación y reportes, cumpliendo los objetivos específicos planteados. 3. **Sobre la arquitectura:** la combinación de los patrones Transaction Script y Service Layer, junto con la estrategia multiempresa de fila compartida, demostró ser adecuada para el dominio: simple y de rápido desarrollo en las operaciones CRUD, y consistente y reutilizable en los flujos críticos de cobranza y facturación. 4. **Sobre la aplicación móvil:** el registro de gestiones con evidencia fotográfica y geolocalización mejora sustancialmente la trazabilidad y la supervisión del cobrador en campo, reduciendo las cobranzas en vano y los reclamos de los clientes. 5. **Sobre la evaluación:** los resultados de las encuestas de satisfacción y las pruebas funcionales evidencian una valoración positiva del sistema (88 % de aprobación en los indicadores principales), confirmando su utilidad para optimizar los procesos de cobranza y el control de la caja diaria. ## 5.2. Recomendaciones 1. **Implementar el sistema en empresas reales** durante períodos prolongados, con el fin de validar los indicadores de reducción de morosidad y de mejora de la eficiencia operativa en condiciones de producción. 2. **Fortalecer la seguridad** mediante auditoría transversal de acciones (módulo de auditoría), control de sesiones activas, políticas de expiración de contraseñas y respaldo automatizado de la base de datos. 3. **Ampliar la cobertura funcional** con: optimización automática de rutas (TSP) sobre las zonas geográficas, notificaciones push avanzadas, firma digital de comprobantes e integración con la facturación electrónica de la SET. 4. **Capacitar continuamente a los usuarios** (administradores, supervisores y cobradores) y mantener actualizada la documentación técnica y los manuales de usuario. 5. **Adoptar buenas prácticas de despliegue:** entornos de desarrollo, prueba y producción; integración continua (CI/CD); y monitoreo del rendimiento de la API y de la base de datos. 6. **Cargar los datos y consumir información directamente desde APIs en lugar de archivos:** migrar progresivamente la carga de clientes, créditos y cuotas desde la importación manual de archivos Excel hacia el consumo directo de servicios web (APIs REST). Para ello se debe exponer un conjunto de endpoints de integración propios, documentados con estándares como OpenAPI/Swagger, y consumir las APIs de sistemas externos (ERP, CRM, banca, pasarelas de pago y facturación electrónica de la SET), de modo que los datos se sincronicen de forma automática, programada y auditable. Esto reduce los errores de digitación, evita la duplicación de registros, elimina los esfuerzos manuales de carga y mantiene la información siempre actualizada entre el sistema de cobranzas y las demás plataformas de la empresa. 7. **Garantizar la disponibilidad e integridad de los datos:** implementar respaldos automatizados de la base de datos con políticas de retención, definir un plan de recuperación ante desastres (con objetivos RPO/RTO claros) y realizar pruebas periódicas de restauración, a fin de asegurar la continuidad operativa del negocio ante fallas o pérdida de información. 8. **Automatizar las pruebas de calidad del software:** incorporar pruebas unitarias, de integración y end-to-end en los módulos críticos (cobranzas, caja diaria y facturación), complementadas con pruebas de carga y rendimiento, y ejecutarlas de manera automática en un pipeline de integración continua para prevenir regresiones antes de cada despliegue. 9. **Optimizar el rendimiento y preparar la escalabilidad:** aplicar índices a las consultas más utilizadas, incorporar una capa de caché (por ejemplo, Redis) para reportes y paneles de control, contenerizar el backend con Docker y evaluar el despliegue en servicios en la nube, con el objetivo de soportar un mayor volumen de empresas, cobradores y operaciones concurrentes. 10. **Mejorar la accesibilidad y la experiencia de usuario:** cumplir pautas de accesibilidad web (WCAG), incorporar modo oscuro, simplificar la navegación y diseñar un proceso de incorporación (onboarding) para nuevos usuarios, a fin de reducir la curva de aprendizaje y ampliar la adopción del sistema tanto en el panel web como en la aplicación móvil. ## 5.3. **Backend:** parte del sistema que procesa la lógica de negocio y gestiona los datos. - **ERP (Enterprise Resource Planning):** sistema de planificación de recursos empresariales que integra procesos como contabilidad, ventas e inventario. - **Machine Learning (aprendizaje automático):** rama de la inteligencia artificial que permite a los sistemas aprender patrones y hacer predicciones a partir de los datos. - **OpenAPI/Swagger:** especificación estándar para describir, documentar y consumir APIs REST de forma estructurada. - **Webhook:** mecanismo mediante el cual un sistema notifica automáticamente a otro cuando ocurre un evento. - **WebSocket:** protocolo de comunicación bidireccional y en tiempo real entre el cliente y el servidor. - **Frontend:** interfaz con la que interactúa el usuario. - **JWT (JSON Web Token):** estándar abierto para la transmisión segura de información entre partes mediante tokens firmados. - **Middleware:** función que se ejecuta en el flujo de una petición HTTP para validaciones, autenticación u otras tareas intermedias. - **Morosidad:** condición de las cuotas o créditos vencidos y no pagados. - **Multiempresa (multi-tenant):** arquitectura que permite a una instancia de software atender a múltiples organizaciones. - **RBAC (Role-Based Access Control):** modelo de control de acceso basado en roles. - **Sprint:** iteración de duración fija en Scrum al término de la cual se entrega un incremento funcional. - **Timbrado:** autorización de la SET para emitir comprobantes fiscales. - **TSP (Traveling Salesman Problem):** problema de optimización que busca la ruta más corta que visita un conjunto de puntos. - **Transacción:** secuencia de operaciones sobre la base de datos que se ejecuta de forma atómica. --- # Abreviaturas | Abreviatura | Significado | |---|---| | API | Application Programming Interface | | BD | Base de Datos | | BI | Business Intelligence | | CD | Continuous Delivery / Continuous Deployment | | CI | Continuous Integration | | CRM | Customer Relationship Management | | CRUD | Create, Read, Update, Delete | | CSRF | Cross-Site Request Forgery | | DSS | Decision Support System | | ERP | Enterprise Resource Planning | | GPS | Global Positioning System | | HTTP | Hypertext Transfer Protocol | | JSON | JavaScript Object Notation | | JWT | JSON Web Token | | MIS | Management Information System | | ML | Machine Learning | | RBAC | Role-Based Access Control | | REST | Representational State Transfer | | RPO | Recovery Point Objective | | RTO | Recovery Time Objective | | SET | Subsecretaría de Estado de Tributación | | SI | Sistema de Información | | SQL | Structured Query Language | | TPS | Transaction Processing System | | TSP | Traveling Salesman Problem | | WCAG | Web Content Accessibility Guidelines | | XSS | Cross-Site Scripting | --- # Referencias Bibliográficas -
